How Do You Check Whether AI Crawlers Can Read a Site?

By CassaInnova · Updated 20 September 2026

Load the site with a crawler's user agent instead of a browser's. See whether it gets the same page a person would. Not a block page, a challenge, or empty content that only appears after JavaScript runs.

Check robots.txt too. Most access problems show up in one of those two places.

What Does "Can AI Crawlers Read a Site" Actually Mean?

It means a named crawler can request a page. Think the crawlers behind ChatGPT, Perplexity, Gemini, and Google's AI features. And get back the same content a person would see.

A site can look completely normal in a browser. It can still be invisible to those crawlers, because the block usually isn't visual.

  • Fetch is the first gate. Can the crawler retrieve the page at all? Or does it get a block, a challenge, or a redirect loop?
  • What's actually in the response matters too. A page can be fetchable and still hand back a near-empty shell. That happens when the real content only renders client-side.

How Do You Check What robots.txt Actually Allows?

Open the site's robots.txt in a private browser tab. It's a plain text file at the domain root, always worth reading first.

Look for a disallow line matching a known crawler. Or worse, a blanket disallow left over from a staging environment.

  • A disallow naming a known crawler token blocks that crawler from the paths listed. Full stop.
  • A blanket disallow for everyone is the single most common accident. A staging rule that shipped to production and never got noticed.
  • A missing or broken robots.txt isn't automatically a pass. A server error on that file reads to many crawlers as a site-wide block.

How Do You Check Whether Something Is Blocking a Crawler at the Edge?

robots.txt is a request. A CDN or bot-management layer can ignore it entirely.

It can serve a challenge page or a 403 before the request ever reaches the site. The only way to see this is to actually send a request as that crawler, and read what comes back.

  • A browser's developer tools can override the outgoing user agent. That's the free way to send that request, no paid tool needed.
  • A matching response — same status, same body — is what a pass looks like. A challenge or a different, thinner page is the finding.
  • This step needs written authorization for the site. The same as any check that sends requests under a non-default identity.

How Do You Check Whether the Content Is Even in the HTML?

A crawler generally reads what the server sends back. Not what JavaScript builds in the browser afterward.

View-source, not the rendered page, is the honest test. If text you can read on screen isn't in that raw response, a crawler that doesn't execute scripts never sees it.

  • Copy a distinctive phrase from the visible page. Then search for it in view-source with Ctrl+F.
  • Missing means client-side-only rendering. Real for many modern frameworks, and a genuine blocker if a crawler doesn't execute the script.
  • Tables and accordions are the usual culprits. Content that's technically "on the page" but never in the response a crawler gets.

What's the Difference Between "Can Fetch" and "May Use"?

Some crawler tokens control whether a page can be fetched at all. Others control whether already-fetched content may be used for a specific downstream product.

Blocking the first stops a crawler cold. Blocking the second can leave fetching untouched, while restricting what the fetched content is allowed to feed.

Fetch vs. use

What's blockedWhat it actually stops
A fetching crawlerThe page is never read at all — the most severe outcome.
A use-control tokenFetching continues; a specific downstream use of the content is restricted instead.
  • A fetch-blocking token in robots.txt is the more severe finding. The page is never read at all.
  • A use-restricting token is a narrower rule. Read it carefully before naming which platform it actually affects — the two are easy to conflate.
  • Reading only the first matching token you find is how a wrong diagnosis gets delivered confidently. Check the general fetching token in the same file first.

What Do You Do With What You Find?

A blocked fetcher is worth calling out immediately. It stops everything else from mattering until it's fixed. This sits inside the same broader pass described in how to check whether a client is cited, and alongside a separate, much smaller question: does llms.txt actually do anything.
